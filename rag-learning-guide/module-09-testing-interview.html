Day 1Test strategy, fixtures, and mocks

1. Why this matters

Here is what running the reference project's test suite on your laptop printed this week: 

2 failed, 126 passed, 31 warnings, 13 errors in 137.58s (0:02:17)

Of those 15 problems, only one is a real bug in the code under test, and even that one is a test that went stale when someone else changed the code. The other 14 are tests that can't run on your laptop, because they need Docker's private network or an internet connection that your office proxy blocks. A suite like that trains everyone to ignore red. Interviewers ask "how did you test it?" because the answer shows whether you can tell those two kinds of failure apart. Today you learn the vocabulary and the tools.

2. Concepts

Three kinds of test

KindWhat it exercisesSpeedIn this project
UnitOne function or class, with everything it talks to replaced by fakesMillisecondstests/unit/, e.g. test_citations.py
IntegrationYour code plus one real outside thing: a real Redis, a real OpenSearch, the real arXiv APISecondstests/integration/test_services.py
End-to-endThe whole running system, from HTTP request to answerMinutes on your CPUscripts/eval_hallucination.py against the live stack

The usual advice is a test pyramid: many unit tests (fast, precise), fewer integration tests, very few end-to-end tests. An end-to-end run of the agent takes about 6 minutes here, so you can't run it on every change. A unit test of one node takes a millisecond.

A test is hermetic when it depends on nothing outside the test process: no network, no containers, no files it didn't create. Hermetic tests give the same result on your laptop, a colleague's laptop, and a CI server.

Fixtures and conftest.py

A fixture is a function marked @pytest.fixture that builds something a test needs. A test asks for it by naming it as a parameter; pytest calls the fixture and passes the result in. A fixture that uses yield instead of return runs setup before the yield and cleanup after the test finishes.

Fixtures in a file named conftest.py are shared with every test in that folder and the folders below it, without any import. If two fixtures have the same name, the one closest to the test wins: a fixture defined in the test file beats one in tests/api/conftest.py, which beats one in tests/conftest.py. Fixtures can also ask for other fixtures. uv run pytest --fixtures tests/unit/services/agents lists every fixture a folder can see and where it comes from.

Test doubles: Mock, MagicMock, AsyncMock

ToolWhat it does
Mock()An object that accepts any attribute or method call and records it. m.get("k") returns another Mock unless you set m.get.return_value.
return_valueWhat the call returns.
side_effectAn exception to raise, or a list of values to return one per call.
MagicMock()A Mock that also supports Python's special methods: with, len(), iteration.
AsyncMock()A Mock whose calls return something you can await. Use it for any async def you replace.
assert_called_once(), call_args, assert_not_called()Check afterwards how the fake was used.

patch: replace a name while a test runs

patch("a.b.name") swaps the attribute name in module a.b for a Mock, and puts the original back afterwards. The rule that trips everyone up: patch where the name is looked up, not where it is defined. from x import f copies a reference to f into the importing module at import time. Patching x.f later doesn't change that copy. You'll see this rule cause 13 errors on Day 3.

tests/unit/services/test_telegram.py · patch, done right

    @patch("src.services.telegram.factory.get_settings")

src/services/cache/factory.py · what you'll test today

def make_cache_client(settings: Settings) -> CacheClient:
    """Create exact match cache client."""
    try:
        redis_client = make_redis_client(settings)
        cache_client = CacheClient(redis_client, settings.redis)
        logger.info("Exact match cache client created successfully")
        return cache_client
    except Exception as e:
        logger.error(f"Failed to create cache client: {e}")
        raise

make_redis_client calls client.ping(). If Redis is unreachable, the error is logged and re-raised. src/main.py calls app.state.cache_client = make_cache_client(settings) in the lifespan without a try, so the API refuses to start without Redis. The cache is only "graceful" per request, inside CacheClient:

src/services/cache/client.py · find_cached_response, shortened

        try:
            cache_key = self._generate_cache_key(request)
            ...
            cached_response = self.redis.get(cache_key)
            ...
        except Exception as e:
            logger.error(f"Error checking cache: {e}")
            return None

Any Redis error becomes a cache miss, and the request carries on to search and the LLM. Both behaviours are worth a test.

4. Build

No new dependencies today. Write tests/unit/services/test_cache_client.py. It uses a plain Mock in place of the Redis client, so it runs with Redis stopped.

Spec, one test each:

  1. Two AskRequests that differ only in category order produce the same key, and the key starts with exact_cache:.
  2. Changing model changes the key. (Why must it? An answer from the 1B model shouldn't be served to someone who asked for the 3B model.)
  3. When redis.get returns a stored response's JSON, find_cached_response returns an equal AskResponse.
  4. When redis.get raises redis.ConnectionError, find_cached_response returns None.
  5. store_response passes ex=timedelta(hours=6) to redis.set when ttl_hours=6.
  6. make_cache_client raises when make_redis_client fails. Patch make_redis_client where make_cache_client looks it up.

        answer="Retrieval-augmented generation [arXiv:2005.11401].",
        sources=["https://arxiv.org/pdf/2005.11401.pdf"],

def test_key_ignores_category_order(cache):
    first = AskRequest(query="What is RAG?", categories=["cs.AI", "cs.LG"])
    second = AskRequest(query="What is RAG?", categories=["cs.LG", "cs.AI"])

    assert cache._generate_cache_key(first) == cache._generate_cache_key(second)
    assert cache._generate_cache_key(first).startswith("exact_cache:")


def test_key_changes_with_model(cache):
    small = AskRequest(query="What is RAG?", model="llama3.2:1b")
    large = AskRequest(query="What is RAG?", model="llama3.2:3b")

    assert cache._generate_cache_key(small) != cache._generate_cache_key(large)


async def test_hit_returns_the_stored_response(cache, fake_redis, response):
    fake_redis.get.return_value = response.model_dump_json()

    assert await cache.find_cached_response(AskRequest(query="What is RAG?")) == response


async def test_redis_error_counts_as_a_miss(cache, fake_redis):
    fake_redis.get.side_effect = redis.ConnectionError("Error 11001 connecting to redis:6379")

    assert await cache.find_cached_response(AskRequest(query="What is RAG?")) is None


async def test_store_sets_the_ttl(cache, fake_redis, response):
    fake_redis.set.return_value = True

    assert await cache.store_response(AskRequest(query="What is RAG?"), response) is True
    assert fake_redis.set.call_args.kwargs["ex"] == timedelta(hours=6)


def test_factory_fails_fast_when_redis_is_down():
    with patch("src.services.cache.factory.make_redis_client", side_effect=redis.ConnectionError("down")):
        with pytest.raises(redis.ConnectionError):
            make_cache_client(get_settings())

Testing _generate_cache_key directly touches a "private" method (leading underscore). It's acceptable here because the key rules are the behaviour you care about; the alternative is inspecting what redis.get was called with, which tests the same thing less readably.

Hint: call_args.kwargs

fake_redis.set.call_args records the last call. .args is the tuple of positional arguments, .kwargs the dictionary of keyword arguments. The client calls self.redis.set(cache_key, ..., ex=self.ttl), so ex is a keyword.

6. Break it

  1. Change the patch target to "src.services.cache.client.make_redis_client". You get an AttributeError saying the module does not have that attribute. patch refuses to create names that don't exist, which protects you from typos. Change it back.
  2. In test_redis_error_counts_as_a_miss, delete the await. The test fails: you're comparing a coroutine object to None, and pytest warns it was "never awaited".
  3. Set fake_redis.get.side_effect = KeyError("bug"). The test still passes. The client's except Exception treats a programming bug exactly like Redis being down. Is that what you want? It keeps answers flowing, but a real bug in the cache code would hide behind a log line. Good interview material.

Day 2Testing the API and the agent

1. Why this matters

Endpoints and the LangGraph agent are where this project's behaviour lives, and both depend on slow or unreliable things: OpenSearch, Jina, and an LLM that takes minutes on your CPU and doesn't answer the same way twice. You need to test the logic (fall back to BM25 when embedding fails, refuse when grading finds nothing, strip fake citations) without any of those services. There are two ways in: FastAPI's dependency overrides for endpoints, and a scripted fake LLM for the agent.

2. Concepts

app.dependency_overrides

app.dependency_overrides is a dictionary on the FastAPI app. Its keys are dependency functions such as get_opensearch_client; its values are replacement functions. When an endpoint declares opensearch_client: OpenSearchDep, FastAPI checks the dictionary first and calls your replacement instead. The endpoint code doesn't change. You must clear the dictionary after the test, or the override leaks into the next test.

TestClient, with and without with

TestClient(app) sends requests straight into the app in-process, with no server and no port. Created plainly, it does not run the lifespan, so no startup code connects to anything. Created as with TestClient(app) as c:, it runs startup and shutdown. For dependency-override tests you want the first form.

A scripted LLM

Every node gets its model through runtime.context.ollama_client.get_langchain_model(...), sometimes followed by .with_structured_output(SomeModel), then calls await ...ainvoke(prompt). If ollama_client is a Mock, you can decide what each ainvoke returns, in order. The test then reads like a script: "the guardrail says 90, the grader says yes then no, the model writes this draft, the checker says grounded."

3. Walkthrough: real code

tests/api/routers/test_agentic_ask.py · dependency overrides

@pytest.fixture
def client(mock_agentic_rag_service):
    """FastAPI test client with mocked dependencies."""
    # Override the dependency to return our mock service
    def override_get_agentic_rag_service():
        return mock_agentic_rag_service

    app.dependency_overrides[dependencies.get_agentic_rag_service] = override_get_agentic_rag_service

    yield TestClient(app)

    # Clean up after test
    app.dependency_overrides.clear()

This fixture is also called client, like the one in tests/api/conftest.py. The one in the test file is closer, so it wins. TestClient(app) isn't used with with, so the lifespan never runs. That's why these 11 tests passed on your laptop while their 13 neighbours errored. The fixture's mock_agentic_rag_service is a Mock(spec=AgenticRAGService): spec makes the Mock reject attributes the real class doesn't have, so a typo like service.aks fails instead of silently returning another Mock.

4. Build

Part A: endpoint tests with dependency overrides

Write tests/api/routers/test_hybrid_search_overrides.py. Spec:

  • Fixtures opensearch (a Mock: health_check returns True, search_unified returns one hit) and embeddings (a Mock whose embed_query is an AsyncMock returning 1024 floats).
  • A local client fixture that overrides get_opensearch_client and get_embeddings_service, yields a plain TestClient(app), then clears the overrides.
  • Four tests: hybrid mode passes the embedding to search_unified; an embedding failure falls back to BM25 with query_embedding=None; OpenSearch unhealthy gives 503 and no search; an invalid body gives 422 before OpenSearch is touched.

tests/api/routers/test_hybrid_search_overrides.py

from unittest.mock import AsyncMock, Mock

import pytest
from fastapi.testclient import TestClient
from src.dependencies import get_embeddings_service, get_opensearch_client
from src.main import app

HIT = {"arxiv_id": "1706.03762", "title": "Attention Is All You Need", "chunk_text": "Self-attention...", "score": 0.016}


@pytest.fixture
def opensearch():
    client = Mock()
    client.health_check.return_value = True
    client.search_unified.return_value = {"hits": [HIT], "total": 1}
    return client


@pytest.fixture
def embeddings():
    service = Mock()
    service.embed_query = AsyncMock(return_value=[0.1] * 1024)
    return service


@pytest.fixture
def client(opensearch, embeddings):
    app.dependency_overrides[get_opensearch_client] = lambda: opensearch
    app.dependency_overrides[get_embeddings_service] = lambda: embeddings
    yield TestClient(app)
    app.dependency_overrides.clear()


def test_hybrid_search_sends_the_query_embedding(client, opensearch):
    response = client.post("/api/v1/hybrid-search/", json={"query": "attention", "size": 1})

    assert response.status_code == 200
    assert response.json()["search_mode"] == "hybrid"
    assert response.json()["hits"][0]["arxiv_id"] == "1706.03762"
    assert opensearch.search_unified.call_args.kwargs["query_embedding"] == [0.1] * 1024


def test_embedding_failure_falls_back_to_bm25(client, opensearch, embeddings):
    embeddings.embed_query.side_effect = RuntimeError("Jina unreachable")

    response = client.post("/api/v1/hybrid-search/", json={"query": "attention"})

    assert response.status_code == 200
    assert response.json()["search_mode"] == "bm25"
    assert opensearch.search_unified.call_args.kwargs["query_embedding"] is None


def test_opensearch_down_returns_503(client, opensearch):
    opensearch.health_check.return_value = False

    response = client.post("/api/v1/hybrid-search/", json={"query": "attention"})

    assert response.status_code == 503
    opensearch.search_unified.assert_not_called()


def test_invalid_request_never_reaches_opensearch(client, opensearch):
    response = client.post("/api/v1/hybrid-search/", json={"query": "attention", "size": 0})

    assert response.status_code == 422
    opensearch.health_check.assert_not_called()

lambda: opensearch is a tiny function with no parameters that returns the fixture's Mock. FastAPI calls it in place of get_opensearch_client(request). The HIT dictionary only needs the fields the router reads with .get(...); missing ones become None.

Part B: the whole agent graph with a scripted LLM

Your Module 8 node tests check one node at a time. Now test the compiled graph: the real AgenticRAGService, real edges, real routing, with only the LLM, OpenSearch, and Jina faked by the fixtures in your agents conftest.py. Write tests/unit/services/agents/test_graph_flow.py with three tests:

  1. Guardrail score 10: the answer is the out-of-scope message, the LLM was called once, OpenSearch was never searched, sources is empty.
  2. The happy path, with exactly five LLM responses in graph order: guardrail 90, grade "yes", grade "no", a draft citing a real and a fake ID, groundedness "yes". Check the fake citation was removed, only the relevant paper is a source, and chunks_used is 1.

Hint: why does grading consume "yes" then "no" in that order?

The grading node starts one coroutine per document with asyncio.gather. They start in list order, and each calls ainvoke before its first real wait, so the first document takes the first queued response. The fake search returns 1706.03762 (Vaswani) first, then 1810.04805 (Devlin).

Hint: why a Mock(content=...) for the draft?

generate_answer reads response.content. A Mock with a content attribute is the smallest thing that looks like an AIMessage.

If you built the optional on-demand ingestion None of these tests reach the "max retrieval attempts" branch, so they don't depend on it. That branch is where the reference repo's one failing unit test lives: another session changed the node's message and didn't update its test.

Day 3Hermetic tests, coverage, ruff, and CI

1. Why this matters

Continuous integration (CI) means a server runs your checks on every push, so nobody merges broken code. A CI server has no Docker network named redis, no Ollama, and no .env. Before CI can help, your suite must be hermetic. Today you fix the reference's 13 host-only errors in your own project, measure how much code your tests exercise, and automate lint and tests on GitHub.

2. Concepts

TermMeaning
CoverageWhich lines of src ran during the tests. pytest-cov measures it. High coverage doesn't prove the tests check anything (the rewrite-query test covers the fallback and asserts almost nothing), but low coverage proves code is untested.
LinterA tool that flags suspicious or inconsistent code without running it. ruff check.
FormatterA tool that rewrites layout (spacing, line breaks, quotes) to one style, so diffs show real changes only. ruff format.
MarkerA label on a test, like @pytest.mark.integration. pytest -m "not integration" runs everything else.
GitHub ActionsGitHub's CI. A YAML file in .github/workflows/ lists jobs; each job runs steps on a fresh virtual machine.

Block by block:

  • LifespanManager(app) (from asgi-lifespan) runs the app's lifespan startup, and shutdown at the end. ASGITransport sends httpx requests straight into the app, in-process. Together they give an async client for the real app with its real startup.
  • The two PostgreSQLDatabase patches replace methods on the class. Every instance sees the change, so these work.
  • The OpenSearch, arXiv, and PDF parser patches replace names in the factory modules. But src/main.py did from src.services.opensearch.factory import make_opensearch_client at import time and holds its own reference. I checked: with the factory patched, src.main.make_opensearch_client is still the real function; patching src.main.make_opensearch_client replaces it. The same applies to OllamaClient, which the Ollama factory imported by name.
  • Nothing patches make_cache_client at all. The lifespan calls it, it pings redis:6379, the name redis doesn't exist on your laptop, and setup fails with Error 11001 connecting to redis:6379. getaddrinfo failed. That's every test using this fixture: 6 in test_ask.py, 6 in test_hybrid_search.py, 1 in test_ping.py. Thirteen.
What happened here: 13 tests that needed the Docker network The errors looked like a Redis problem, and "start Redis" wouldn't have fixed them, because the hostname only exists inside Docker. The real cause was a fixture that patched the wrong names, and a lifespan with no fallback when Redis is missing. Inside the API container they happened to pass, against real services, which is why nobody noticed.

3. Walkthrough: real code

One request, end to end: POST /api/v1/ask-agentic

  1. FastAPI parses the body into AskRequest (422 on bad input) and resolves AgenticRAGDep:

src/dependencies.py

def get_agentic_rag_service(
    opensearch: OpenSearchDep,
    ollama: OllamaDep,
    embeddings: EmbeddingsDep,
    langfuse: LangfuseDep,
    settings: Annotated[Settings, Depends(get_settings)],
) -> AgenticRAGService:
    """Get agentic RAG service."""
    return make_agentic_rag_service(
        opensearch_client=opensearch,
        ...
        model=settings.ollama_model,
    )

Notice this runs per request: every call builds a new AgenticRAGService, which compiles the LangGraph graph in its constructor. The clients come from app.state (created once in the lifespan) so that part is cheap, but the compile is repeated. A good "what would you change?" answer: build the service once in the lifespan and store it on app.state.

  1. ask() rejects an empty query, opens a Langfuse trace if tracing is on, and runs the graph with a fresh Context holding the clients and the requested model.
  2. guardrail: one LLM call with GuardrailScoring. Below 60 → out_of_scope → end.
  3. retrieve writes an AIMessage with a tool call; tools_condition routes to tool_retrieve, which runs retrieve_papers: Jina embed_query, then OpenSearch search_unified (hybrid, RRF), returning text for the LLM and Documents as the artifact.
  4. grade_documents: one LLM call per chunk, concurrently with asyncio.gather; failures exclude the chunk. None relevant → rewrite_query → retrieve again, up to 2 attempts.
  5. generate_answer from the relevant chunks only; verify_answer strips unretrieved citations, rejects unknown "Surname et al.", then asks the LLM whether the answer is grounded. Not grounded → refusal plus source links.
  6. The router builds AgenticAskResponse: answer, source URLs, chunks_used, removed_citations, answer_grounded, reasoning steps.

With 3 chunks that's 1 + 3 + 1 + 1 = 6 LLM calls, which is why the agentic endpoint takes about 6 minutes on your CPU and /ask (one call) takes 2–4.

Trade-off questions, with the facts to answer them

QuestionFact from this codebase to anchor your answer
Anything wrong with hybrid_search?It calls synchronous opensearch_client.search_unified(...) inside async def, blocking the event loop per search. The agent's tool does the same.
GPU or CPU?CPU: 2–4 min per answer with a 1B model. A GPU cuts that to seconds and lets concurrent grading actually run in parallel.
Exact or semantic cache?The cache key is a sha256 of query, model, top_k, use_hybrid, sorted categories. "What's RAG?" and "What is RAG?" miss each other.
Chunk size?600 words with 100 overlap, section-aware. Smaller chunks are more precise but lose context and multiply embedding calls.
BM25, vector, or hybrid?Hybrid with RRF, falling back to BM25 when Jina fails. RRF scores (around 0.016) are rank-based, not comparable to BM25 scores.
1B or larger model?The 1B model invented IDs and authors; hardened, it often refuses. 3B answers more often, but more slowly on CPU.
Local or hosted LLM?Local: free, private, slow here. Hosted: fast, costs per token, data leaves your machine. Embeddings are already hosted (Jina).
How does ingestion scale?One Airflow task, semaphores for concurrent downloads and parsing, a 3-second arXiv rate limit. At scale: a queue with parallel workers, idempotent re-indexing.
What happens if Redis is down?At request time, a cache miss. At startup, the API fails, because make_cache_client re-raises and the lifespan doesn't catch it.

Your five debugging stories

1. The proxy and the hash mismatch Situation: the Airflow image build failed with "THESE PACKAGES DO NOT MATCH THE HASHES" on large wheels like torch. Action: noticed it was intermittent and only on big downloads, traced it to the TLS-inspecting corporate proxy corrupting or truncating large transfers; added the corporate CA to the images and a BuildKit pip cache mount with a retry loop. Result: builds succeed, and retries reuse what was already downloaded.
2. "Make sure the API server is running" Situation: Gradio said the API was down, but /health was fine. Action: read the underlying exception instead of the friendly message: an httpx read timeout at 60 s, while CPU inference takes 2–4 minutes. Result: 600 s timeout; lesson about error handlers that replace the real error with a guess.
3. The stale cached answer Situation: after adding the citation safeguards, one question still returned hallucinated citations. Action: realised the answer came from Redis, cached before the fix, with a 6-hour TTL; flushed it. Result: correct answers; and a design point: cache keys should include a version of the answer pipeline, so a logic change invalidates old entries.
4. Fabricated citations Situation: /ask cited 2304.06476 and 2305.08659 while only 2609.30227 and 2609.30558 were retrieved; the prompt's example ID made the 1B model emit 2301.00001; it invented "Rasmussen et al.", and the LLM groundedness check passed it. 5. Thirty-minute rebuilds Situation: every API rebuild took about 30 minutes. Action: found Docker's build cache at its 30 GB limit, evicting the big dependency layer each time. Result: understood layer caching as a cost, not theory; pruning and ordering layers so dependencies change rarely.

Interview drill

Answer each question out loud before opening the model answer. Then message me "Drill me on Module 9" and I'll run a full mock interview: architecture, trade-offs, one story, and follow-ups.

1. How did you test this project?
Three levels. Unit tests with fakes for every service: citation checks, cache keys, each agent node, and the whole LangGraph graph with a scripted fake LLM. API tests that run the real FastAPI app and lifespan in-process, with factories patched to fakes or dependencies overridden. A few marked integration tests plus an evaluation script against the live stack. CI runs everything except integration tests, with ruff and coverage.
2. How do you test code that calls an LLM?
Replace the model with an AsyncMock whose side_effect is a list of responses, returned in call order. Structured outputs are just Pydantic objects, so the fake returns GradeDocuments(binary_score="yes") directly. Put an exception in the list to test failure handling. Then assert on behaviour and on the call count, for example "the author check refused without calling the LLM". Model quality is measured separately, with an eval script on real questions.
3. What does "patch where it's looked up" mean? Give the bug you found.
from x import f copies a reference into the importing module, so patching x.f doesn't affect it. The reference API fixture patched src.services.opensearch.factory.make_opensearch_client, but the lifespan uses src.main.make_opensearch_client, and it didn't patch the cache factory at all. So the lifespan tried to reach redis:6379 and 13 tests errored on any machine outside Docker. Patching the names in src.main fixed it.
4. Dependency overrides versus patch: when do you use each?
app.dependency_overrides replaces what FastAPI injects into an endpoint, cleanly and without touching imports; ideal for endpoint tests without the lifespan. patch replaces any name anywhere, needed for things that aren't dependencies: the lifespan's factories, or code that constructs objects itself, like the health endpoint's OllamaClient(settings). Needing patch often is a sign the code should take the object as a parameter.
5. What's a fixture, and what is conftest.py for?
A fixture builds something a test needs; tests request it by parameter name, and yield fixtures clean up afterwards. conftest.py shares fixtures with every test in its folder and below, without imports; the closest definition wins. Missing conftest fixtures don't skip tests, they error, which is how 22 agent tests had never run.
6. What does code coverage tell you, and what doesn't it?
Which lines ran during tests. It can't tell you whether anything was checked: the course's rewrite-query test covers the fallback branch, passes, and never tests the LLM path its name claims. Use coverage to find untested code, and good assertions to make covered code meaningful.
7. Walk me through one /ask-agentic request.
Validate AskRequest; build the service via AgenticRAGDep; guardrail LLM score (below 60 goes to out-of-scope); retrieve node emits a tool call; the tool embeds the query with Jina and runs hybrid search in OpenSearch; each chunk is graded by the LLM concurrently; none relevant means rewrite and retry, up to 2 attempts; generate from relevant chunks only; verify: strip unretrieved citations, reject unknown authors, LLM groundedness check, otherwise refuse with source links; return answer, sources, removed citations, grounded flag, reasoning steps. About 6 LLM calls, about 6 minutes on this CPU.
8. The search endpoint is async def. Is it non-blocking?
No. It calls the synchronous OpenSearch client inside async def, so each search blocks the event loop and every other request waits. Fixes: the async OpenSearch client, await asyncio.to_thread(...), or a plain def endpoint, which FastAPI runs in a thread pool.
9. How would you serve 100 concurrent users?
The LLM is the bottleneck: move inference to a GPU server (or a hosted model) that batches requests. Fix blocking calls in async endpoints, build the agent service once instead of per request, run several API workers behind a load balancer, add a semantic cache for paraphrased questions, and stream answers so users see progress. Ingestion is separate and scheduled, so it scales on its own.
10. Exact-match or semantic cache?
This project uses exact match: a hash of query, model, top_k, hybrid flag, and sorted categories. It's safe (a hit is always the same question) but misses paraphrases. A semantic cache embeds the question and reuses answers above a similarity threshold: more hits, but the risk of serving an answer to a subtly different question. Both need invalidation when the pipeline changes; I learned that from a stale cached answer that still had fabricated citations.
11. Why hybrid search, and why RRF?
BM25 nails exact terms, model names, and IDs; vectors catch paraphrases. RRF combines the two rankings using only ranks, 1/(k + rank), so the incompatible raw scores never need to be compared. That's why the final scores look tiny, around 0.016. If embedding fails, the endpoint falls back to BM25 instead of erroring.
12. Tell me about a hard bug.
Pick one of your five stories and use STAR. Strong choice: fabricated citations. The 1B model cited papers that were never retrieved and invented authors, and an LLM-based check approved it. I added deterministic checks before the LLM judge, graded chunks individually, made every failure path refuse, and wrote tests plus an eval script to measure it. The trade-off: the small model now refuses more often.
