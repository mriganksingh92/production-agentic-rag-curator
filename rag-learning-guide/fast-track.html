Day 14: the clients

The app talks to two outside services. Each gets a small class holding a shared httpx.AsyncClient, the same shape as the reference project's clients. Taking the HTTP client as a constructor argument is what makes them testable: the tests pass in a client whose transport returns canned responses, so no network is involved.

  • capstone/settings.py: CapstoneSettings (pydantic-settings, prefix CAPSTONE__, reads .env) with search_url = "http://localhost:8000/api/v1/hybrid-search/", ollama_url = "http://localhost:11434", model = "llama3.2:1b", and timeout_seconds = 600.0.
  • capstone/clients.py:
    • SearchClient(http, search_url) with async search(query: str, size: int) -> list[dict]: POSTs {"query", "size", "use_hybrid": True}, raises on an error status, returns the reply's "hits".
    • OllamaClient(http, base_url, model) with async generate(prompt: str) -> str: POSTs to {base_url}/api/generate with "stream": False and "options": {"temperature": 0, "num_predict": 300}, raises on an error status, returns "response".
Hint: raising on an error status

response = await self.http.post(...), then response.raise_for_status(), which turns 4xx and 5xx replies into httpx.HTTPStatusError.

Day 15: the /ask endpoint

Now the app itself, in capstone/app.py. The clients are created once at startup in a lifespan function and stored on app.state; dependency functions hand them to the endpoint. That's exactly how the reference project wires its services (src/main.py and src/dependencies.py), and it's what lets the tests replace both clients with fakes.

  • NO_CONTEXT_ANSWER, a module-level string: a polite refusal saying no relevant passages were found, so you won't guess.
  • AskRequest: query (1–1000 characters, required), top_k (int 1–10, default 3).
  • AskResponse: query, answer, sources: list[str], chunks_used: int, removed_citations: list[str].
  • A lifespan that loads CapstoneSettings, opens one httpx.AsyncClient with the configured timeout, stores a SearchClient and an OllamaClient on app.state, and closes the HTTP client on shutdown.
  • app = FastAPI(title="Mini Paper Curator", lifespan=lifespan), with dependency functions get_search_client(request) and get_ollama_client(request) that return those objects, and GET /health returning {"status": "ok"}.
  • POST /ask: search with top_k. No hits: return NO_CONTEXT_ANSWER without calling the LLM (fail closed). Otherwise: sources are the hits' arXiv IDs without duplicates, in order; generate from build_prompt(query, hits); clean the draft with strip_unverified_citations(draft, sources); return everything, with chunks_used = number of hits.
Hint: the lifespan 
@asynccontextmanager
async def lifespan(app: FastAPI):
    settings = CapstoneSettings()
    async with httpx.AsyncClient(timeout=settings.timeout_seconds) as http:
        app.state.search_client = ...
        app.state.ollama_client = ...
        yield

Everything before yield runs at startup; leaving the async with block at shutdown closes the client.

Hint: duplicates removed, order kept

list(dict.fromkeys(hit["arxiv_id"] for hit in hits)). Dictionaries keep insertion order and can't have duplicate keys.

tests/capstone/test_app.py

from fastapi.testclient import TestClient

from capstone.app import NO_CONTEXT_ANSWER, app, get_ollama_client, get_search_client

HITS = [{"arxiv_id": "2609.30227v1", "title": "To Trust or Not to Trust", "chunk_text": "Speech fact checking needs retrieval."}]


class FakeSearch:
    def __init__(self, hits):
        self.hits = hits

    async def search(self, query, size):
        return self.hits[:size]


class FakeLLM:
    def __init__(self, reply):
        self.reply = reply
        self.prompts = []

    async def generate(self, prompt):
        self.prompts.append(prompt)
        return self.reply


def client_with(search, llm):
    app.dependency_overrides[get_search_client] = lambda: search
    app.dependency_overrides[get_ollama_client] = lambda: llm
    return TestClient(app)


def teardown_function():
    app.dependency_overrides.clear()


def test_ask_returns_the_answer_and_its_sources():
    llm = FakeLLM("Retrieval helps fact checking [arXiv:2609.30227v1].")
    response = client_with(FakeSearch(HITS), llm).post("/ask", json={"query": "What helps fact checking?"})

    assert response.status_code == 200
    body = response.json()
    assert body["answer"] == "Retrieval helps fact checking [arXiv:2609.30227v1]."
    assert body["sources"] == ["2609.30227v1"]
    assert body["chunks_used"] == 1
    assert body["removed_citations"] == []
    assert "What helps fact checking?" in llm.prompts[0]


def test_made_up_citations_are_removed():
    llm = FakeLLM("Retrieval helps [arXiv:2609.30227] [arXiv:2304.06476].")
    body = client_with(FakeSearch(HITS), llm).post("/ask", json={"query": "q"}).json()

    assert body["removed_citations"] == ["2304.06476"]
    assert "2304.06476" not in body["answer"]


def test_no_passages_means_no_llm_call():
    llm = FakeLLM("should never be used")
    body = client_with(FakeSearch([]), llm).post("/ask", json={"query": "q"}).json()

    assert body["answer"] == NO_CONTEXT_ANSWER
    assert body["sources"] == []
    assert llm.prompts == []


def test_bad_request_is_rejected_with_422():
    response = client_with(FakeSearch(HITS), FakeLLM("x")).post("/ask", json={"query": "", "top_k": 50})
    assert response.status_code == 422

TestClient(app) without a with block doesn't run the lifespan, so no real clients are created; the overrides supply the fakes. teardown_function runs after every test in the file and removes the overrides, so one test's fakes can't leak into the next. Exercise B: hybrid ranking with RRF (Day 6)

Hybrid search runs two searches, one by keywords (BM25) and one by meaning (vectors), and must merge two ranked lists whose scores aren't comparable. Reciprocal Rank Fusion ignores the scores and uses only positions: each document gets 1 / (k + rank) from every list it appears in, summed, with k = 60 by convention. A document near the top of both lists beats one at the very top of only one. OpenSearch does this inside its search pipeline; you'll write it by hand so you can explain it.

Write fasttrack/rrf.py with rrf_fuse(rankings: list[list[str]], k: int = 60) -> list[tuple[str, float]]: takes several ranked lists of document IDs (best first) and returns (doc_id, score) pairs, highest score first.

Hint

A dictionary of running totals; enumerate(ranking, start=1) gives you ranks starting at 1; then sorted(scores.items(), key=lambda item: item[1], reverse=True).

tests/fasttrack/test_rrf.py

import pytest

from fasttrack.rrf import rrf_fuse


def test_single_list_scores():
    fused = rrf_fuse([["a", "b"]])
    assert [doc for doc, _ in fused] == ["a", "b"]
    assert fused[0][1] == pytest.approx(1 / 61)
    assert fused[1][1] == pytest.approx(1 / 62)


def test_documents_ranked_well_in_both_lists_win():
    keyword = ["a", "b", "c"]
    vector = ["d", "a", "c"]
    fused = rrf_fuse([keyword, vector])
    assert [doc for doc, _ in fused] == ["a", "c", "d", "b"]
    assert fused[0][1] == pytest.approx(1 / 61 + 1 / 62)


def test_why_hybrid_scores_look_tiny():
    top_score = rrf_fuse([["only"]])[0][1]
    assert top_score == pytest.approx(0.0164, abs=0.0001)

Exercise C: a mini RAG pipeline (Day 8)

The whole idea of the project in one file: retrieve passages, put them in a prompt, ask the LLM, return the answer with its sources. You'll use the reference stack's search endpoint and its Ollama directly.

Write fasttrack/mini_rag.py:

  • build_prompt(question: str, chunks: list[dict]) -> str: tells the model to answer using ONLY the excerpts and to cite the bracketed arXiv IDs, or say the excerpts don't contain the answer. Lists every chunk as [arXiv:{arxiv_id}] {title} followed by its chunk_text, and puts the question after the excerpts.
  • search(question: str, size: int = 3) -> list[dict]: the hybrid search call from Exercise A, returning the raw hits.
  • generate(prompt: str, model: str = "llama3.2:1b") -> str: POSTs to http://localhost:11434/api/generate with {"model", "prompt", "stream": False, "options": {"temperature": 0, "num_predict": 200}} and returns the reply's "response" field. Use a 600-second timeout: on your CPU this takes minutes.
  • ask(question: str) -> dict: search, build the prompt, generate, and return {"answer": ..., "sources": [...]}, where sources are the hits' arXiv IDs without duplicates.
  • A __main__ block that asks the question in sys.argv[1] and prints the answer and sources.
Why temperature goes inside options Ollama ignores a top-level temperature; it only reads it inside options. That's an easy mistake, and you can't see it without checking.

from fasttrack.mini_rag import build_prompt

CHUNKS = [
    {"arxiv_id": "2609.30227v1", "title": "To Trust or Not to Trust", "chunk_text": "Speech fact checking needs retrieval."},
    {"arxiv_id": "2609.30558v1", "title": "Agent Memory", "chunk_text": "Memory systems keep long-term facts."},
]


def test_prompt_contains_the_question_and_every_chunk():

    assert "What is RAG?" in prompt

def test_prompt_restricts_the_model_to_the_excerpts():

def test_question_comes_after_the_excerpts():

    assert prompt.index("Memory systems") < prompt.index("What is RAG?")
