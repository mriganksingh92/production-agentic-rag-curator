Day 1Set up your project, then typed Python and Pydantic

1. Why this matters

Data in this project crosses many boundaries: from your browser into the API, from the API into OpenSearch, from the LLM back into Python. Every boundary is a place where the data can arrive in the wrong shape: a missing field, a string where a number should be, an LLM that answers "Yes!" instead of "yes". The codebase handles this in two ways. Type hints document what shape data should have. Pydantic checks that it really does, while the program runs.

2. Concepts

Your toolbox for today

The reference repo uses exactly this setup: open its pyproject.toml and you'll see the dependency list, and uv.lock pins the exact version of every package so everyone installs identical code.

Type hints

A type hint is a label saying what type a value should be: def get_latest_query(messages: List) -> str says "takes a list, returns a string". Python itself does not check hints when the program runs. They exist for readers, editors (autocomplete, warnings), and tools like Pydantic. Re-read section 1, item 6 ("Type Hints") and the Optional part of section 19 in your masterclass notes. The ones you'll see most here:

HintMeans
List[str] or list[str]A list of strings
Dict[str, Any]A dictionary with string keys and values of any type
Optional[str]A string, or None
Literal["yes", "no"]Exactly one of these values
-> boolThe function returns a bool

Dataclass versus Pydantic model

Both turn a list of typed fields into a class with a constructor, so you don't write __init__ by hand. The difference:

@dataclassPydantic BaseModel
Checks types at runtime?NoYes, and converts where sensible ("7" becomes 7)
Rules like "between 1 and 10"?NoYes, via Field(ge=1, le=10)
Converts to and from JSON?Not built inYes: model_dump_json(), Model(**data)
Used in this project forInternal plumbing, e.g. the agent's Context holding live client objectsAnything crossing a boundary: API requests and responses, LLM output, settings
Rule of thumbUse Pydantic where data enters from outside your code. Use a dataclass for objects your own code creates.

3. Walkthrough: real code

src/schemas/api/ask.py · the body of every /ask request

class AskRequest(BaseModel):
 Inheriting from BaseModel is what makes this a Pydantic model. Creating one runs validation.
    query: str = Field(..., description="User's question", min_length=1, max_length=1000)
 ... (Python's "Ellipsis") as the first argument means required: no default. The length limits reject an empty question, and stop someone sending a 5 MB "question".
    top_k: int = Field(3, description="Number of top chunks to retrieve", ge=1, le=10)
 Default 3. ge = greater or equal, le = less or equal. top_k=50 is rejected before any search runs.
    use_hybrid: bool = Field(True, description="Use hybrid search (BM25 + vector)")
 A plain default. You'll learn what hybrid search is in Module 4.
    model: str = Field("llama3.2:1b", description="Ollama model to use for generation")
 Which local LLM answers. The same field that the agentic endpoint used to ignore until today's fix.
    categories: Optional[List[str]] = Field(None, description="Filter by arXiv categories")
 Either a list like ["cs.AI"], or None meaning "no filter".
    class Config:
        json_schema_extra = {...}
 An example shown on the /docs page. This inner-Config style is from Pydantic v1; v2 prefers model_config = ConfigDict(...), which is why the test run prints deprecation warnings.

When a request arrives, FastAPI builds an AskRequest from the JSON body. If validation fails, FastAPI answers with 422 Unprocessable Entity and a list of what was wrong, and your endpoint code never runs.

src/services/agents/models.py · Pydantic as a contract with the LLM

class GradeDocuments(BaseModel):
    binary_score: Literal["yes", "no"] = Field(description="Document relevance: 'yes' or 'no'")
    reasoning: str = Field(default="", description="Explanation for the decision")

The grading step calls llm.with_structured_output(GradeDocuments). LangChain turns this class into a JSON schema, asks the model to answer in that shape, and validates the reply. If the model says "Yes!", validation fails; the grading step catches that and excludes the chunk. The same class that validates API input here validates LLM output.

Hint: the arXiv ID rule

Field(pattern=r"^\d{4}\.\d{4,5}(v\d+)?$"). Read it as: start, 4 digits, a dot, 4 or 5 digits, optionally "v" plus digits, end.

Hint: a list default

Never write authors: list[str] = [] in a dataclass; every instance would share one list. Pydantic copies defaults safely, but the habit worth building is Field(default_factory=list).

Hint: removing the version

re.sub(r"v\d+$", "", text) replaces "v plus digits at the very end" with nothing. Call .strip() first.

Day 2Decorators, context managers, generators, and pytest

1. Why this matters

Almost every file in the project uses at least one of @something, with, or yield. They look like magic until you've written one. After today you'll read @router.post, async with httpx.AsyncClient(), and a streaming endpoint as ordinary Python. Re-read section 16 (Comprehensions & Generators) and section 17 (Decorators & Context Managers) in your masterclass first.

2. Concepts

Decorators

In Python a function is a value, like a number: you can pass it to another function and get a function back. A decorator is a function that takes a function and returns a replacement. Writing @timed above def f is shorthand for f = timed(f).

A decorator with arguments, like @retry(times=3), has one more layer: retry(times=3) runs first and returns the real decorator, which is then applied to f. So f = retry(times=3)(f). Decorators usually wrap the function with functools.wraps, which copies the original name and docstring onto the replacement so logs and tools still see the right name.

Context managers

A with block guarantees that setup and cleanup happen in pairs, even if an error is raised halfway: a file gets closed, a network connection gets released, a tracing span gets ended. with X() as y: calls X().__enter__() (its return value becomes y), runs your block, and always calls __exit__ at the end.

Generators

A function containing yield doesn't run when you call it. It returns a generator, which produces one value each time someone asks for the next one, pausing in between. That makes generators ideal for streaming: sending an answer word by word as the LLM produces it, instead of waiting for the whole thing. An async def with yield is an async generator, consumed with async for.

pytest in one paragraph

pytest finds files named test_*.py, runs every function named test_*, and reports any assert that fails. pytest.raises checks that an error happens. @pytest.mark.parametrize runs a test once per input. @pytest.fixture defines reusable setup that tests receive as arguments. The reference repo's tests/unit/services/agents/conftest.py is a real example; those fixtures were missing until today, so 22 agent tests had never run.

src/gradio_app.py · context managers, and a bug they were part of

async with httpx.AsyncClient(timeout=httpx.Timeout(600.0, connect=10.0)) as client:
 Opens an HTTP client with a connection pool. When the block ends, even through an error, the pool is closed. Without the with, a crash would leak open connections.
    async with client.stream("POST", url, json=payload, headers={"Accept": "text/plain"}) as response:
 A second context manager: one streaming request. Leaving the block releases the connection back to the pool.
        async for line in response.aiter_lines():
 Reads the response one line at a time as it arrives: an async generator on the client side.
What happened here this week The timeout used to be 60.0. On your laptop's CPU the model needs 2–4 minutes per answer, so httpx gave up at 60 seconds. The error was caught by a handler that printed "make sure the API server is running", so the UI blamed a server that was fine. The fix was this one argument. Lesson: read the actual exception, not the friendly message someone wrapped around it.

4. Build

Write playground/wrappers.py with:

  1. timed: a decorator. The wrapped function returns the same result as before, still has its original __name__, and stores how long its last call took, in seconds, on an attribute named last_seconds.
  2. retry(times, exceptions=(Exception,)): a decorator factory. Calls the function up to times times; if every attempt raises, re-raises the last error. This is the same idea as the retry loop that got the Airflow build through your proxy.
  3. Timer: a context manager class. with Timer() as t: measures the block, then t.seconds holds the duration.
  4. chunk_text(text, size, overlap=0): a generator that yields pieces of size characters, each starting size - overlap characters after the previous one. Stop after yielding the piece that reaches the end of the text. Empty text yields nothing. Raise ValueError if overlap >= size. The reference project splits papers the same way, with overlap so a sentence cut at a boundary still appears whole in one piece. You'll build the real version in Module 4.
Hint: the shape of a decorator 
def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        ...  # start clock, call func(*args, **kwargs), stop clock
    wrapper.last_seconds = 0.0
    return wrapper

*args, **kwargs accept any arguments and pass them through unchanged. Use time.perf_counter() for timing.

Hint: a decorator factory

Three nested functions: retry(times) returns decorator(func), which returns wrapper(*args, **kwargs). Inside wrapper, loop times times with try/except exceptions; remember the last error and raise it after the loop.

Hint: the generator loop

Keep a start index. Each loop: end = start + size, yield the slice, stop if end >= len(text), otherwise move start forward by size - overlap.

Day 3async and await

1. Why this matters

Your masterclass notes don't cover this, and it's everywhere in the project. The API spends most of its time waiting: for OpenSearch to search, for Jina to embed, for Ollama to write. Async code lets one Python process do other useful work during those waits, such as serving another user's request, or grading three chunks at once instead of one after another.

2. Concepts

The kitchen picture. One cook (one Python thread) has three pots to boil. A synchronous cook puts pot 1 on the stove and stands staring at it until it boils, then starts pot 2. An asynchronous cook puts pot 1 on, and while it heats, puts pots 2 and 3 on too, then serves whichever boils first. Same cook, same stove, far less standing around. Async doesn't make the stove hotter; it only removes idle waiting.
TermMeaning
async def f()Defines a coroutine function. Calling f() doesn't run it; it creates a coroutine object, a paused piece of work.
await x"Run x, and while it waits, let other coroutines run. Resume me when it's done." Only allowed inside async def.
Event loopThe scheduler that runs coroutines and switches between them at every await. asyncio.run(main()) starts one; FastAPI and pytest-asyncio start one for you.
asyncio.gather(a, b, c)Runs several coroutines concurrently and returns their results in the same order you passed them.
I/O-boundWaiting on a network, disk, or another program. Async helps.
CPU-boundComputing, like a model running on your CPU. Async doesn't help, because nothing is waiting.
The trap: blocking inside async A normal (synchronous) call like time.sleep(1) or requests.get(...) inside an async def doesn't pause politely; it freezes the whole event loop, so every other request waits too. Inside async code, use the async version: await asyncio.sleep(1), httpx.AsyncClient.

3. Walkthrough: real code

src/services/agents/nodes/grade_documents_node.py · grading chunks concurrently

async def _grade_document(grader, question: str, document: Document) -> GradingResult:
 A coroutine function that grades one chunk. The leading underscore signals "internal helper, not for use outside this file".
    document_id = document.metadata.get("arxiv_id", "unknown")
 .get(key, default) avoids a crash if the key is missing.
    try:
        grade: GradeDocuments = await grader.ainvoke(
            GRADE_DOCUMENTS_PROMPT.format(context=document.page_content, question=question)
        )
 Fills the prompt template, sends it to the LLM, and awaits the reply. While this waits on Ollama, the event loop can start grading the other chunks. ainvoke is LangChain's naming for "async invoke".
        is_relevant = grade.binary_score == "yes"
        return GradingResult(...)
 Turns the LLM's structured answer into a result record.
    except Exception as e:
        logger.warning(f"Grading failed for {document_id}, excluding it: {e}")
        return GradingResult(document_id=document_id, is_relevant=False, ...)
 Fail closed: if grading breaks, the chunk counts as irrelevant rather than slipping through. You'll see this pattern throughout Module 8.

And the line that runs them all at once, further down the same file:

    results = await asyncio.gather(*(_grade_document(grader, question, doc) for doc in documents))

The part in brackets is a generator expression producing one coroutine per chunk; * unpacks them into separate arguments. gather runs them concurrently, and results lines up with documents by position.

Honest nuance, and a good interview point Concurrency only overlaps the waiting. Ollama on your CPU may still work through the three prompts one at a time, so grading might not get 3× faster here. On a GPU server handling parallel requests, it would.

src/routers/hybrid_search.py · spot the issue

@router.post("/", response_model=SearchResponse)
async def hybrid_search(
    request: HybridSearchRequest, opensearch_client: OpenSearchDep, embeddings_service: EmbeddingsDep
) -> SearchResponse:
    ...
        results = opensearch_client.search_unified(
            query=request.query,
            ...
        )
What's wrong? Think first, then open.

search_unified is a normal, synchronous call to OpenSearch, made inside an async def with no await. While OpenSearch answers, the event loop is frozen and no other request is served. At one user, nobody notices. Fixes: use an async OpenSearch client, or declare the endpoint with plain def, because FastAPI runs non-async endpoints in a thread pool so they don't block the loop. Finding issues like this in real code is exactly what interviewers want to hear about.

Day 4HTTP, JSON, settings, and logging

1. Why this matters

Every part of this system talks to the others over HTTP with JSON: your browser to the API, the API to OpenSearch, Ollama, and Jina. When something fails, the status code and the response body tell you which hop failed and why. And every service reads its configuration (URLs, keys, limits) from environment variables, so the same code runs on your laptop, inside Docker, and on a server.

2. Concepts

An HTTP exchange

Request partExample from this project
MethodGET to read, POST to send a body. Search and ask use POST because the question travels in a JSON body.

Settings from the environment

An environment variable is a named value the operating system hands to a program when it starts. A .env file is a convenient list of them. Keeping settings there instead of in code means different values per machine without editing code, and secrets like your Jina API key stay out of git. pydantic-settings reads them into a validated model, so a typo like TIMEOUT=abc fails immediately at startup instead of mysteriously later.

Logging

Nearly every file in the project starts with logger = logging.getLogger(__name__). __name__ is the module's import path (like src.routers.ask), so each log line says where it came from. Levels, from quiet to loud: DEBUG, INFO, WARNING, ERROR. Those API log lines we read today, like WARNING - Answer cites authors not in the retrieved papers, came from exactly this.

Day 5Docker and Compose

1. Why this matters

The reference project is 13 programs: PostgreSQL, OpenSearch, Redis, Ollama, Airflow, the API, and the Langfuse services. Installing each one by hand, in the right version, on every laptop and server would take days and never match exactly. Docker packages each program with everything it needs. Compose starts them all with one command, connected on a private network. You've already run docker compose up; today you'll understand every line of it.

2. Concepts

TermMeaning
ImageA read-only package: an operating system base, the program, its libraries. Like a class. Example: redis:7-alpine.
ContainerA running instance of an image, with its own processes and filesystem. Like an object created from the class. You can run many from one image.
DockerfileThe recipe for building your own image, one instruction per line.
Layer and cacheEach Dockerfile instruction produces a layer. Docker reuses unchanged layers on rebuild, which is why the order of instructions matters for build speed.
Port mapping "16379:6379"HOST:CONTAINER. Traffic to port 16379 on your laptop is forwarded to port 6379 inside the container.
VolumeStorage that outlives the container. Remove and recreate the container, and the data is still there.
NetworkContainers in the same Compose project can reach each other by service name: the API connects to redis:6379. That name only exists inside the network.
HealthcheckA command Docker runs periodically to decide whether the service is actually ready, not just started.
What happened here this week Every API rebuild took about 30 minutes. The image's biggest layer (all the Python packages, torch included) is normally cached, but Docker's build cache had reached 30 GB, its cleanup limit, so that layer kept being deleted and re-downloaded through your proxy. Layers and caching aren't theory; they decide whether a deploy takes 30 seconds or 30 minutes.

Interview drill

Answer each question out loud or in writing before opening the model answer. Then message me "Drill me on Module 0" and I'll ask them in a different order, with follow-ups.

1. What's the difference between a type hint and a Pydantic model?
Type hints are annotations for readers and tools; Python ignores them at runtime. A Pydantic model uses the same hints to validate and convert data when an object is created, and raises ValidationError on bad input. In this project, AskRequest rejects top_k=50 before any search runs, and FastAPI turns that into a 422 response.
2. When would you pick a dataclass over a Pydantic model?
For internal objects your own code constructs, where validation adds nothing. The agent's Context holds live client objects and a few settings, so it's a dataclass. Anything crossing a boundary (HTTP bodies, LLM output, config) is Pydantic.
3. What is a decorator? Explain what @tool(response_format="content_and_artifact") does.
A decorator takes a function and returns a replacement: @d on f means f = d(f). With arguments, tool(response_format=...) runs first and returns the actual decorator. Here it wraps retrieve_papers in a LangChain tool object with a name, a description from the docstring, and ainvoke. The response format makes the tool return both text for the LLM and the raw documents for the code.
4. What problem do context managers solve? Give an example from the project.
They guarantee cleanup runs even if an error happens inside the block. The Gradio client uses async with httpx.AsyncClient(...) so connections are always released, and the RAG endpoint wraps generation in a tracing context manager so the span is always closed. Bonus: that same client's 60-second timeout caused the "server not running" false alarm.
5. What is a generator, and why does streaming use yield?
A function with yield returns a generator that produces values one at a time, pausing in between. The /stream endpoint yields each piece of text as Ollama produces it, and StreamingResponse sends it immediately, so the user sees the answer build up instead of waiting minutes for the whole thing.
6. Explain async/await to someone who isn't an engineer.
One cook with several pots: instead of staring at one pot until it boils, the cook starts all of them and tends whichever is ready. The program does other work while it waits on the network, instead of sitting idle. It removes waiting; it doesn't make any single task faster.
7. What happens if you call an async function without await?
You get a coroutine object and nothing runs. Python warns "coroutine was never awaited" when it's garbage-collected. A common bug: if check_something(): on an async function is always true, because a coroutine object is truthy.
8. The agent grades three chunks with asyncio.gather. Is grading now three times faster?
Not necessarily. gather overlaps the waiting, but if Ollama on one CPU processes prompts one at a time, the work is still sequential underneath. On a GPU server that handles parallel requests, it would be faster. Knowing where the real bottleneck is matters more than the keyword.
9. What's wrong with a synchronous network call inside async def? Where does the project do this?
It blocks the event loop, so every other request waits until it returns. hybrid_search calls the synchronous search_unified inside an async def endpoint. Fixes: an async OpenSearch client, or a plain def endpoint, which FastAPI runs in a thread pool.
10. What do 404, 422, 500, and 503 mean in this API?
404: no endpoint at that path. 422: the request body failed validation or wasn't valid JSON, and your code never ran. 500: your code raised an unexpected exception. 503: a dependency is down; hybrid_search returns it when OpenSearch fails its health check. The code tells you which hop to investigate.
11. Why keep settings in environment variables instead of in code?
The same code runs in different places (laptop, Docker, production) with different values, and secrets like API keys stay out of git. pydantic-settings validates them at startup, so a bad value fails fast with a clear error instead of breaking later.
12. Image versus container? Dockerfile versus Compose?
An image is a read-only package; a container is a running instance of it. A Dockerfile is the recipe for building one image; Compose describes how several containers run together: ports, volumes, environment, network, health checks, and startup order.
13. Why does the API reach Redis at redis:6379, while your laptop must use localhost:6379?
Compose puts the containers on a private network with built-in DNS, where each service name is a hostname. Your laptop isn't on that network, so redis doesn't resolve; that's the getaddrinfo failed error. Your laptop reaches Redis through the published port mapping on localhost.
